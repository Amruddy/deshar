# Release Candidate Release 1.0

## 1. Статус

Документ фиксирует состояние stage `Release Candidate Smoke And Notes` в рамках
`Release 1.0`.

Рабочая ветка stage:

`feat/release-candidate-smoke-notes`

Первый release-candidate blocker по журналу и сводной посещаемости
преподавателя закрыт ранее в PR #58:

- журнал группы открывается преподавателем;
- страница урока доступна из группы и журнала, если есть созданные уроки;
- `/teacher/attendance` показывает рабочую сводку по ученикам преподавателя;
- `smoke:roles` проверяет `/teacher/attendance` как рабочий раздел по маркеру
  `data-attendance-summary="ready"`.

## 2. Что покрыто release-candidate smoke

### 2.1. Роли и закрытые маршруты

- Неавторизованный пользователь перенаправляется с закрытых маршрутов на
  `/login`.
- Администратор открывает свою рабочую область и не получает доступ к
  преподавательской или ученической рабочей области.
- Преподаватель открывает свою рабочую область, группы, учеников, журнал,
  уроки, посещаемость, домашние задания, материалы и оплаты.
- Ученик открывает свою рабочую область, расписание, домашние задания,
  материалы, прогресс, посещаемость и оплаты.
- Чужие рабочие области блокируются через `/forbidden` без раскрытия данных.

### 2.2. Auth-flow

- Supabase Auth email/password вход проверен для администратора, преподавателя
  и ученика.
- Supabase Auth user связан с доменным `users.auth_user_id`.
- Активные роли проверены через `organization_members`.
- `/profile` открывается под каждой ролью.
- Logout очищает auth-сессию.
- Пользователь с `users.auth_status = disabled` не проходит session resolver.
- Dev-auth остается доступным только по локальному флагу
  `DESHAR_ENABLE_DEV_AUTH=1`.

### 2.3. Журнал и посещаемость преподавателя

- `/teacher/groups` возвращает рабочий список групп преподавателя.
- Из списка групп найдены ссылки на карточку группы, журнал группы и страницу
  урока.
- `/teacher/groups/[groupId]/journal` возвращает месячный журнал с таблицей,
  формой сохранения и полями быстрых отметок `mark__...`.
- `/teacher/attendance` возвращает страницу со сводкой посещаемости и рабочим
  маркером `data-attendance-summary="ready"`.

## 4. Оставшиеся ограничения Release 1.0

- Нет публичной самостоятельной регистрации.
- Нет OAuth, SSO, MFA и passkeys.
- Нет родительских аккаунтов.
- Нет массовых bulk-приглашений.
- Нет онлайн-оплаты и billing-интеграций.
- Нет загрузки файлов, PDF, аудио и видео.
- Нет чата, автоматических уведомлений и видеозвонков.
- Нет сложной аналитики, отчетов и графиков за пределами рабочих сводок.
- Нет production deploy, домена, backup-политики и мониторинга.
- `smoke:auth` предназначен для локального/dev Supabase проекта и не должен
  запускаться против production Supabase.

## 5. Release notes

`Release 1.0` готовится как рабочий release candidate для школы таджвида:

- production auth через Supabase Auth заменяет dev-only вход для реального
  использования;
- администратор управляет курсами, группами, учениками, преподавателями и
  ручным учетом оплат;
- преподаватель ведет группы, журнал, уроки, посещаемость, прогресс, домашние
  задания, материалы и видит сводку посещаемости;
- ученик видит расписание, домашние задания, материалы, прогресс,
  посещаемость и оплату;
- интерфейс приведен к единой Release 1.0 дизайн-системе;
- основные role/auth smoke-проверки проходят локально на release-candidate
  ветке.

Следующий ожидаемый шаг после ручной проверки: commit и push ветки
`feat/release-candidate-smoke-notes` для pull request.
